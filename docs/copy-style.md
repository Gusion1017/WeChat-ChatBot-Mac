# 文案与提示规范

> 面向 WeChat AI 所有可见界面（SwiftUI）与本地化。目标：**一句话说清「做什么 / 为什么 / 下一步」**，
> 术语一致、按钮可预期、长解释可收起。实现组件见 `DesignSystem/Controls.swift` 的 `HelpTip`
> 与 `app/Sources/WeChatBot/Models/Localization.swift`。

## 1. 基本原则

1. **简洁优先**：标题能说清的，不再加副标题；副标题能说清的，不再加通知。同一信息只出现一次。
2. **操作信息必须可见**：风险、前置条件、不可逆后果、需要用户手动做的步骤，一律写在正文里，
   不能只放进悬停提示。
3. **解释性内容可收起**：原理、背景、边界条件、数据位置、性能说明等，用行内一句短说明 +
   标题旁的「?」提示（`HelpTip`）承载。
4. **可直接执行**：错误与等待状态要给「下一步」（重试 / 去设置 / 先启动机器人），不要只描述现象。
5. **不营销**：不用「强大」「极致」「轻松」等形容词，不用感叹号；用事实和结果说话。
6. **不重复**：标题、副标题、状态行、按钮不重复同一句话；卡片内已说明的，不再加同义通知。

## 2. 术语表（必须一致）

| 概念 | 统一写法 | 避免 |
| --- | --- | --- |
| 产品名 | WeChat AI | 微信智能助手、微信 AI 助手、本程序 |
| 运行实体 | 机器人 | Bot、机器人程序 |

| 本地 OneBot 桥 | bridge | Bridge、桥接服务（首次出现可写「bridge」） |

| 模型页 | AI 模型 | AI 设置、模型设置 |

| 记忆 | 记忆卡 / 全量记录 / 记忆库 | 记忆条目、存档 |

版本号、文件名、代码保持原样；中文与拉丁字母/数字之间加一个空格（如「AI 模型」「约 4.7 GB」），
中文与中文标点之间不加空格。

## 3. 句式与标点

- 标题：名词短语或动词短语，≤ 12 个汉字，不加句号。例：「捕获发送句柄」「自动发布」。
- 副标题 / 说明：一个完整短句，≤ 30 个汉字；需要时最多两句。用中文全角标点。
- 按钮：动词开头，2–6 个汉字。例：「重新检测」「保存设置」「打开 AI 模型页」。
  需要继续输入或打开面板时加省略号（「添加通道…」）；纯即时动作不加。
- 状态：短名词/形容词。例：「已就绪」「待完成」「不可用」「未开启」。
- 成功 Toast：动词 + 已。例：「评论已发布」「设置已保存」。
- 失败 Toast / 通知：动作 + 失败：原因 + 下一步。例：「安装失败：权限不足。请退出微信后重试。」
- 数字与单位：`12 秒`、`4.7 GB`、`10%`、`3 条`；时间范围用 `–`（如 `09:00–18:00`）。
- 引用界面元素用「」，引用代码/字段用反引号，英文专名保留原大小写。
- 不用「请稍候」重复堆叠；等待状态必须说明在等什么（或可以离开）。

## 4. 分场景规则

### 卡片 / 页面头部
- 标题只描述内容；副标题只补充范围或状态，不复述标题。
- 依赖链写清楚（如「依赖 R3 原生发送，未开启时语音改用文字」），但只写一次。

### 设置行
- 标题：设置项名称；副标题：当前值或一句影响说明（≤ 24 字）。
- 更长的原因、限制、数据位置放进 `help`（问号提示）。
- 行标题不携带状态；状态用右侧控件/气泡表达。

### 空态
- 标题说「没有什么」，正文说「为什么 / 怎么开始」，附一个主操作。
- 不写与页面标题重复的句子。

### 错误与未就绪
- 先给结论，再给原因，最后给下一步；不暴露内部堆栈/路径（除非供排障复制）。
- 禁用控件必须在同一行/卡片内解释为什么灰（可见文字，不是仅 tooltip）。

### 确认弹窗
- 标题：动作本身（「删除通道」）；正文：影响范围与是否可撤销；
- 破坏性按钮使用危险色，文案与标题一致（「删除」），不使用「确定」。

### Toast
- 只报告结果，不复述操作过程；同一事件不重复弹。
- 错误 Toast 与行内错误二选一即可，二者同时出现时不要同文重复。

## 5. 问号提示（HelpTip）

```swift
HelpTip(text: "解释性文字")                    // 独立图标，悬停约 0.6 秒显示
SectionCard(title: "…", help: "…") { … }      // 标题右侧问号
SettingsRow(title: "…", help: "…") { … }      // 行标题右侧问号
FormField(label: "…", help: "…") { … }        // 表单标签右侧问号
SettingsSection(title: "…", help: "…") { … }  // 分组标题右侧问号
```

使用规则：
- 只放**解释**：原理、为什么需要、数据保存在哪、性能/额度的边界、失效时机。
- 每条 ≤ 120 个汉字、1–3 句；使用陈述句，不写按钮名（按钮在正文里）。
- 一行/一个分组最多一个问号；同一段解释不要在多处重复。
- **不得**把风险、前置条件、需要用户执行的步骤只放进 `HelpTip`。
- 悬停提示不是唯一入口：VoiceOver 通过 `accessibilityHint` 读取同一段解释。

## 6. 本地化（en.lproj）

- 中文是源语言；每条 `L("中文")` / `Text("中文")` 的英文翻译写在
  `app/Packaging/en.lproj/Localizable.strings`，key 必须与中文完全一致。
- 英文风格：句首大写、完整句用句号、按钮用祈使句、状态用短语；术语按 §2 映射
  （机器人 = bot，通道 = channel，人格 = persona，记忆卡 = memory card，发送句柄 = send handle）。
- 占位符原样保留：`%@`、`%d`、插值变量；动态拼接文案优先用 `L10n` 的 pattern，不在视图里拼英文。
- 新增/修改中文文案时同步补英文；未翻译的 key 在英文界面会回退为中文。
- 中文界面不要求维护 `zh-Hans.lproj` 恒等表；缺 key 时自动回退中文源串。
