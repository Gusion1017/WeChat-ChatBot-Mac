# 微信 4.2.1.5 (270597) 适配说明

> 适配日期：2026-11-25 · 对应 App **4.2.2 (build 40)** · 目标微信 **4.2.1.5 (270597)**

## 结论

- 新增 `hook/versions/4_2_1_5_mac.json`，并切为默认目标；4.2.1.3 (270595) 与 4.2.0.x 版本表继续保留。
- 地址表由 4.2.1.3 静态重定位生成：**58/58 个地址键全部为 `verified` / `high`**
  （0 个 `medium` / `review` / `unresolved`）。结构类键由 RTTI、vtable、ctor/size 与工作目录内
  反汇编交叉确认；函数与数据键由函数锚点、指令窗口和 xref 投票确认。
- `hookVerified=true`；4.2.1.5 已从 `WeChatVersionSupport.unverifiedHookVersions` 的语义中移出
  （该集合保持为空）。
- 朋友圈**写**链路（发布 / 评论 / 回复 / 主动同步）尚未在 4.2.1.5 复测，`snsWriteSuppressedVersions`
  暂含 `4.2.1.5`，App 强制只读；朋友圈读取与时间线使用同一套已验证地址。

## 升级

1. 完全退出微信。
2. 安装 Hook（会自动备份当前微信）：

   ```bash
   bash tools/manage_wechat.sh install
   ```

3. 启动微信与机器人；首次启用 R3 发送前，在 Mac 微信里手动发一条消息捕获发送句柄。
4. App 会在确认当前微信账号的数据目录后自动创建空的 `temp/`，首次启动/微信更新后不必再先打开
   一张聊天图片。若仍提示找不到图片临时目录，通常是重装/重签后 macOS 的「App 数据 / 完全磁盘
   访问」授权失效：在 系统设置 → 隐私与安全性 中把 WeChat AI 关闭再打开（或重新添加），完全退出
   并重开 App 后重试。
5. 从源码反复重建 App 时，先运行 `bash scripts/configure_codesign_identity.sh` 固定本机签名身份；
   ad-hoc 签名每次构建都会变，会让 TCC / Keychain 授权反复失效。发布包仍默认 ad-hoc。

安装脚本默认目标已切到 4.2.1.5；4.2.1.3 / 4.2.0.x 仍可通过 `KNOWN_VERSION_PAIRS` 安装。

## 回退

适配前的官方微信备份：

```
~/Library/Application Support/WeChatAI/backups/WeChat-4.2.1.5-270597-official.zip
```

```bash
# 完全退出微信后
bash tools/manage_wechat.sh restore \
  --backup-zip "$HOME/Library/Application Support/WeChatAI/backups/WeChat-4.2.1.5-270597-official.zip"
bash tools/manage_wechat.sh install
```

若微信被 Sparkle 升级到 4.2.1.9 (270601)：该版本**未适配**，App 会阻止 Hook 启动；用上面的
备份回退到 4.2.1.5 后重新安装 Hook，并在微信设置里关闭自动更新。本次适配过程中实测退出微信后
会被自动升级到 4.2.1.9，回退前请确认更新已被关闭。

## 已知限制

- 4.2.1.5 的朋友圈写链路未复测，App 强制只读；赞 / 取消赞 / objectop 与 userpage 主动发送的既有
  限制不变。
- 语音发送、图片下载与群聊 @ 未在 4.2.1.5 全部复测；`task_layout_mismatch` 安全闸保留。
- 仅支持 Apple Silicon / macOS 26+；修改微信仍有签名失效与账号风控风险，请保留官方备份。
